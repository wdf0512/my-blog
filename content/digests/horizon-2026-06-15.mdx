## [Pyodide 现在支持将 WASM wheel 直接发布到 PyPI](https://simonwillison.net/2026/Jun/13/publishing-wasm-wheels/#atom-everything) ⭐️ 8.0/10

Pyodide 314.0 版本引入了对将 WASM wheel 直接发布到 PyPI 的支持，允许包维护者根据 PEP 783 定义的 PyEmscripten 平台标准，自行构建和分发浏览器兼容的 Python 包，无需 Pyodide 维护者手动干预。 此举去中心化了 Pyodide 包生态系统，消除了 Pyodide 维护者此前必须手动审核和构建 300 多个包的瓶颈，并赋予更广泛的 Python 社区像发布原生平台 wheel 一样发布 WebAssembly 兼容包的能力。 Wheel 使用 cp314-cp314-pyemscripten_2026_0_wasm32 标签，可通过 micropip 在运行时安装。PyPI 的支持 PR 于 4 月 21 日合并，cibuildwheel 现在可以生成此类 wheel。作者通过发布一个由 C++ 编译为 WASM 的 luau-wasm 包进行了演示。

rss · Simon Willison · 6月13日 23:55

**背景**: Pyodide 是一个通过 WebAssembly 在浏览器和 Node.js 中运行的 Python 发行版。此前，带有 C/C++ 扩展的包需要 Pyodide 维护者手动编译和托管。PEP 783 定义了针对 Pyodide 运行时的二进制 Python 发行版的 pyemscripten 平台标签，标准化了此类包的识别和安装方式。

## [Adobe RMSDK 宽松解析器致 Kobo 电子书阅读器渲染异常](https://andreklein.net/your-epub-is-fine-kobo-disagrees-blame-adobe/) ⭐️ 7.0/10

一项调查发现，Adobe 的 Reader Mobile SDK (RMSDK) 使用宽松解析器，导致结构无效的 ePub 文件通过验证，而 Kobo 自家的 kepub 渲染引擎能正确拒绝这些文件，最终在 Kobo 设备上造成字体和格式持续不一致的问题。 这使得数百万 Kobo 用户面临碎片化的阅读体验，并使出版商无需修复格式错误的 ePub 文件，破坏了 ePub 标准所追求的跨设备一致渲染目标。 将文件转换为 Kobo 的 kepub 格式（如使用 kepubify 工具）可以绕过有问题的 RMSDK，调用更符合标准的渲染引擎。

**背景**: Adobe RMSDK 是一款被广泛授权的渲染引擎，为包括 Kobo 在内的电子书应用和设备提供支持。Kobo 设备还内置了一个专为其私有 kepub 格式设计的、更现代的独立渲染引擎。ePub 标准由 W3C 维护，并提供 EPUBCheck 验证器以确保文件结构合规。然而，RMSDK 不准确的验证造成了官方标准与实际渲染效果之间的脱节。

## [追踪 SQLite 查询结果列并回溯至源表与列名](https://simonwillison.net/2026/Jun/13/sqlite-column-provenance/#atom-everything) ⭐️ 7.0/10

Simon Willison 尝试通过编程方式为任意的 SQLite 查询结果追溯每一列的来源表与列名，即便查询包含复杂的表连接和公共表表达式（CTE）。 这项能力能让 Datasette 等工具自动为查询结果附加元数据注释，从而为浏览复杂数据库的用户提供更丰富的数据探索手段和更直观的上下文信息。 已发现多种实现方案，包括使用 `apsw` 库直接访问 SQLite 的列元数据 API、利用纯 Python 的 `ctypes` 调用 `sqlite3_column_table_name()` 函数，以及通过分析 `EXPLAIN` 输出进行推断；这些方法都要求 SQLite 在编译时启用 `SQLITE_ENABLE_COLUMN_METADATA` 选项。

rss · Simon Willison · 6月13日 23:05

**背景**: Datasette 是一个流行的 Python 工具，能将 SQLite 数据库转换为交互式网站供人探索与发布。SQL“列溯源”指将查询结果中的某一列追溯至其在数据库中对应的原始表与列字段。SQLite 的 C 库内部可以通过启用 `SQLITE_ENABLE_COLUMN_METADATA` 编译选项来向应用提供此类信息，但 Python 标准库的 `sqlite3` 模块并未公开这一接口。公共表表达式（CTE）是用于简化复杂查询的临时命名结果集，它也增加了列溯源的实现难度。

## [验证器税：LLM 智能体中与任务长度相关的安全-成功权衡研究](https://www.reddit.com/r/MachineLearning/comments/1u58mkq/the_verifier_tax_horizondependent_safetysuccess/) ⭐️ 7.0/10

reddit · r/MachineLearning · /u/AccomplishedLeg1508 · 6月14日 02:09

**背景**: τ-bench 是一个模拟 LLM 智能体与用户在现实场景中进行动态对话的基准测试，其中智能体使用工具帮助用户达成共同目标。在 AI 安全领域，智能体可能通过违反规则达成目标（即不安全成功），这使得评估变得棘手，因为高成功率可能隐藏严重的安全隐患。
