## [Valhalla 项目值类型十年磨一剑，JDK 28 正式引入](https://www.jvm-weekly.com/p/project-valhalla-explained-how-a) ⭐️ 9.0/10

经过十年开发，Valhalla 项目的值类型与增强原生类型终于在 JDK 28 中发布，使得 JVM 能以扁平、紧凑的内存布局存储对象，显著提升性能。 这标志着 Java 对象模型的重大演进，使面向对象抽象能兼得原生类型的性能，大幅降低内存开销与指针间接访问，对高性能计算和数据密集型应用影响深远。 该特性引入不可变且无身份的值对象，支持在数组内联存储，避免对象头与指针追踪。但扁平化仅限于表示大小不超过 64 位的对象，且设计有意不在类型系统中强制空安全，以保持模型简洁。

hackernews · philonoist · 6月19日 06:35 · [社区讨论](https://news.ycombinator.com/item?id=48595511)

**背景**: Project Valhalla 于 2014 年由 Oracle 发起，由 Brian Goetz 领导，旨在弥合 Java 原生类型与对象在抽象和性能上的鸿沟。传统 Java 对象始终带有对象头，数组存储指向堆中对象的指针，导致内存碎片与间接访问开销。值类型通过取消对象身份，使数据直接且连续地存储，避免了这些代价。历经十年设计与社区反馈迭代，核心特性最终在 JDK 28 中正式集成。


**参考链接**:

- [Project Valhalla (Java language)](https://en.wikipedia.org/wiki/Project_Valhalla_(Java_language))
- [Project Valhalla](https://openjdk.org/projects/valhalla/)


**社区讨论**: 社区评论总体肯定 Valhalla 的十年努力，但围绕空安全与扁平化存在争议。有人认为简化模型不必要地牺牲了空安全讨论，另有人指出大于 64 位对象的扁平化不可行，可能误导开发者。部分评论感慨 Java 已远非昔日模样，平台依旧强大，此次发布是追赶的必然一步。

## [ATProto 中没有实例：用 RSS 类比澄清误解](https://overreacted.io/there-are-no-instances-in-atproto/) ⭐️ 8.0/10

Dan Abramov 的文章澄清了 ATProto（Bluesky 背后的协议）没有类似 Mastodon 的“实例”概念。它采用类似 RSS 的架构，用户将数据存储在个人数据服务器（PDS）上，并由中继（Relay）和应用视图（AppView）独立聚合内容。 这一澄清对去中心化社交媒体社区至关重要，因为它揭开了 Bluesky 设计的神秘面纱，并促进了对协议权衡的深入讨论。它还有助于潜在采用者理解 ATProto 如何避免 Mastodon 实例的服务器中心化问题，提供了一种更模块化的去中心化路径。 ATProto 将个人数据存储（PDS）、内容聚合（中继）和展示（应用视图）分离，模仿了 RSS 源独立于聚合器的方式。但中继需要索引整个网络，成本高昂，在实践中可能成为中心化瓶颈，其去中心化程度不如完全自托管的博客。

hackernews · danabramov · 6月19日 15:10 · [社区讨论](https://news.ycombinator.com/item?id=48599515)

**背景**: ActivityPub 是 Mastodon 和 Fediverse 背后的协议，依赖被称为“实例”的服务器来托管多个用户并相互联邦。相比之下，Bluesky 开发的 ATProto 是一种去中心化协议，没有实例，每个用户运行自己的个人数据服务器（PDS）。文章以 RSS 为类比：博客是独立实体，RSS 阅读器（如 Google Reader）聚合它们而不拥有博客。类似地，ATProto 的 PDS 是独立的，中继和应用视图聚合网络中的内容。


**参考链接**:

- [AT Protocol - Wikipedia](https://en.wikipedia.org/wiki/AT_Protocol)
- [Protocol Overview - AT Protocol](https://atproto.com/guides/overview)
- [Fediverse - Wikipedia](https://en.wikipedia.org/wiki/Fediverse)


**社区讨论**: 社区讨论热烈，许多人称赞文章解释清晰，但也对 RSS 类比的准确性提出质疑。有人认为中继是昂贵的中心化瓶颈，文章回避了 ATProto 如何处理实例所解决的去中心化审核问题（如解除联邦）。另一些人则指出，关注点分离是解决扩展问题的优雅方案。
